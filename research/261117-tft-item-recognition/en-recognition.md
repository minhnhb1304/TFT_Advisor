## Cross-source agreement (2 independent repos)

- Under-unit item icon at 1080p is **23x23 px**, step **25-26 px**, max 3, anchored at about **(-5..-8, +8..+14) from the left/top of the green health bar** (TFT-Copilot + Agente-TFT).
- Anchor = the health bar, found by a color mask (`G>110 & G>1.65R & G>1.5B`, plus a dark border to reject foliage) ([hud_regions.py](https://github.com/ZhongliangGuo/TFT-Copilot/blob/main/data/vision_dataset/s18-equipment-v5.1/protocol/hud_regions.py)). No one does sliding-window search over the whole board.
- Handling overlap/VFX: neither repo solves it. Both mark the slot unresolved/conflict instead of guessing. TFT-Copilot uses reciprocal unique bar-to-slot assignment and rejects irregular bar sizes or bars overlapping a neighbour's item box. Both support only the planning phase.
- Small-icon identity: 3 approaches seen. (1) a detector/classifier trained on synthetic composites of the official art (needs a private dataset, sim-to-real gap on radiant). (2) training-free embedding NN (ResNet18 cosine) against the official art, which is robust to frame/scale/tint. (3) RMS/NCC/descriptor gallery search, cheap, but Copilot reports NCC/SSIM confusions and Agente reports RMS-vs-descriptor conflicts on Rod/Bramble.
- 1080p fixed coordinates are the norm (TFT-OCR-BOT, TFT-Copilot). Agente-TFT argues for UI anchors + detected scale.

## Icon sources

- CommunityDragon: `cdragon/tft/en_us.json` has 4230 item entries. The `icon` field looks like `assets/maps/tft/icons/items/hexcore/tft_item_bfsword.tex`. Replace `.tex` with `.png` and prefix `https://raw.communitydragon.org/latest/game/`. Verified 200, **128x128 PNG** (tested 2026-11-17). Filter to the active set; there are many legacy entries.
- Data Dragon: `tft-item.json`, icons under `img/tft-item` ([Riot TFT docs](https://developer.riotgames.com/docs/tft)). Agente-TFT notes Data Dragon can lag a patch, so mark new icons as unknown until it updates.
- In-game 23 px icons are a downscale of this art with no frame. Bench icons are ~50 px with a frame. TFT-Copilot ships its own 23x23 refs ([hud-icons](https://github.com/ZhongliangGuo/TFT-Copilot/tree/main/data/vision_dataset/s18-equipment-v4/reference/hud-icons)).

## Official / allowed data sources

- **Live Client Data API (127.0.0.1:2999)**: responds during TFT (it is a LoL game mode), but Riot has never documented or supported it for TFT. In [RiotGames/developer-relations#865](https://github.com/RiotGames/developer-relations/issues/865), `activeplayer.level` matches TFT level, but `currentGold` is the hidden Summoner's Rift gold counter. No TFT board/bench/item-bench fields have been seen in any source. The local repo already tracks this as unverified (`research/open-questions.md`, `SPEC.md:124`). Not fetched live here, so a 5-minute probe is still needed.
- **Overwolf GEP (TFT)**: exposes exactly the needed data: `board_pieces.cell_N.item_1..3`, `bench_pieces...item_N`, `item_bench` (all players' components, GEP 308+), `carousel_pieces`, `item_select`, `picked_item` ([Overwolf TFT GEP](https://dev.overwolf.com/ow-native/live-game-data-gep/supported-games/teamfight-tactics)). This is a Riot-sanctioned channel but requires the Overwolf runtime. Sibling research `research/261007-overwolf-overlay/` covers it.
- **Riot policy**: overlays may not track opponents' boards or provide "real-time data that would improve a player's performance immediately by altering player behavior" ([Riot TFT docs](https://developer.riotgames.com/docs/tft)). That is relevant if items are used for live advice.
- Riot match-v1 has item data only post-game.

## Unresolved questions

- No public real-match accuracy for any item recognizer. TFT-Copilot gives only qualitative results, and Agente-TFT says outright that it has no real-match accuracy.
- Does the item-bench grid (origin 8,258; pitch 55) still hold at patch 18.6 / VN client? It was calibrated on Set 18 CN screenshots.
- Combat-phase readability (VFX, low-HP bars, moving units): no one has validated it.
- Whether `allgamedata` in TFT exposes any items: needs a live probe.
